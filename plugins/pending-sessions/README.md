# pending-sessions

DSH GUI 插件：**全局悬浮条**，列出等你处理的会话——阻塞等待（等批准 / 等回答 / 计划复核）与回合结束未读回复两类都算，并常显「运行中 / 等你处理 / 完成未读 / 全部空闲」四态。默认在右下角，可长按拖动换位；暂时不方便处理时一键收起，新待处理出现自动恢复。

- 权威设计：[`2026-11-05-pending-sessions-design.md`](../../docs/superpowers/specs/2026-11-05-pending-sessions-design.md)
- 实施计划：[`2026-11-05-pending-sessions-plan.md`](../../docs/superpowers/plans/2026-11-05-pending-sessions-plan.md)

## 适用场景

- 同时开多个工作区 / 会话，想知道「是在等回复，还是没有会话在工作」。
- 窗口切走时希望有新待处理能弹系统通知，回来一点就跳转。
- 不需要手动标记已读：跳转或处理完自动消失。

代价与边界：未读与运行状态是**本次打开 DSH 以来**的客户端内存，刷新页面即丢；`pendingInteraction` 较耐久，但 Host 重启后也会丢。它不是跨重启的待办清单；系统通知依赖浏览器授权与 OS 设置；不替用户决定已读，也不写任何已读表。

## 安装

包已声明 `dsh.bundle.patch`，插件页可直接安装。桌面版或 Web 侧栏 **插件** → **添加插件** → **安装第三方插件**，填：

```
https://github.com/huip1830-debug/dsh-extensions.git#path:/plugins/pending-sessions
```

CLI 等价（profile 名按实际安装位置替换）：

```powershell
dsh plugin --profile desktop add "https://github.com/huip1830-debug/dsh-extensions.git#path:/plugins/pending-sessions"
```

装完在插件页启用，**完全退出并重启 DSH**（profile 层插件不支持热加载），再打开页面。升级 = 同地址重装，或 `dsh plugin --profile desktop update pending-sessions`；卸载 = 插件页移除，或 `dsh plugin --profile desktop remove pending-sessions`。

## 使用

### 状态与颜色

| 状态 | 药丸表现 |
|---|---|
| 有会话运行 | 品牌蓝圆点脉冲 + 「N 运行中」；开启系统「减少动态效果」后降级为静态 |
| 运行中且有待处理 | 颜色 = 最高优先级的「用户动作」：有阻塞类时黄边黄点，只有未读时归运行色；脉冲 = 仍有会话运行；文字「N 运行中 · M 待处理 · K 待读」，缺项省略 |
| 没有运行、有待处理 | 有阻塞类 → 黄边黄点 + 「M 待处理 · K 待读」；只有未读 → 绿边绿点 + 「K 待读」 |
| 没有运行、没有可见待处理 | 三级灰小点 + 「全部空闲」，不警示不闪烁，常显 |

运行计数取整个客户端观察到的运行会话数，**刻意包含子智能体**，作为全局活动指示。

### 待处理来源与排序

| 来源 | 归类 | 说明 |
|---|---|---|
| `pendingInteraction`（等批准 / 等回答 / 计划复核） | 阻塞类 | 算待处理，药丸显示警示色 |
| `completionUnread` | 未读类 | 回合跑完但回复未读 |
| 当前主视图会话 | 不列出 | 已经在眼前 |
| 子智能体会话（`origin: 'subagent'`） | 不列表、不通知 | 运行计数例外；孤儿 id 无法证明是子智能体，照常列出 |
| 父会话等待子智能体 | 不列、不通知、不计待处理 | 整批结束、父会话真正跑完且无活跃子智能体时，这一次未读才按普通未读提醒一次；父会话自己有等批准 / 等回答时照常提醒 |

排序：阻塞类整体在前，未读类在后；两类内部各自按会话更新时间倒序（最新在前）。

### 面板与交互

- **自动展开**：任何新进入待处理的边沿只要在可见列表里，面板直接展开，**不看窗口焦点**。两个例外：页面首次加载 / 连接代际 reset 的基线快照不展开；用户「暂时收起」期间不展开。
- **面板内容**：头部状态摘要行 + 列表项 = 状态点 + 类型标签 + 工作区名 + 会话标题。
- **点击条目**：`ctx.uiWorkspace.openSession(sessionId)`，等价侧边栏点击；跳转使会话成为主视图 → 未读清除，完成交互 → 领域撤销待处理，条目自动消失。
- **关闭（×）**：回到药丸形态，不是临时收起，待处理仍在列表里。
- **暂时收起**：面板头部按钮把当前全部待处理 id 压入控制器内存收起集；药丸不再显示待处理数量、不用警示色（运行动画不受影响），面板仍可查看全部条目。任何不在收起集里的会话新进入待处理 → 收起状态解除、计数与警示色恢复（但面板仍不自动展开）；收起集中的 id 离开待处理后立即清除，之后再次进入算新 episode，同样触发恢复与通知。点击低调药丸或面板「恢复」按钮可手动恢复并展开。刷新页面后收起集复位。

### 拖动与位置

- **手势**：长按药丸 ≥400ms 或按住移动 >10px 进入拖动；药丸浮起并实时跟随指针。两个阈值都未满足的松手仍是原点击行为。**只在收起态可用**，面板展开时位置锁定。
- **落点**：自由放置（不吸附边缘），松手时按当前视口与药丸实测尺寸换算成**比例坐标** `{fx, fy}`（可动区间 = 视口 − 药丸尺寸 − 两侧 8px 边距；`fx=fy=1` 即右下角），写入 `localStorage["pending-sessions/pill-position"]`，跨刷新 / 重启保留。
- **缩放**：窗口缩放 / 最大化后按新视口换算回像素，始终落在同一**相对**位置；旧版 `{left, top}` 像素偏好首次测量后一次性迁移为比例并写回；畸形 / 迁移失败回落右下角默认，绝不丢到窗口外；存储不可用时静默降级为本次内存；连接代际 reset 不复位位置。
- **面板朝向**：药丸在下半屏 → 面板向上展开；上半屏 → 向下展开；水平贴药丸右缘并钳制在视口内（窗口过窄时面板收窄，过矮时限制高度）。

### 系统通知

- 窗口失焦 + 会话新进入待处理 → 弹一条系统通知；多条同时出现合并为一条摘要（「N 个会话待处理」）。
- 窗口聚焦时不弹；页面首次加载时已在待处理的会话只进列表，不补发通知。
- 同一 episode 只通知一次；处理掉之后再次进入才算新 episode；已收起项不重复通知。
- 权限被拒 / 环境不支持 → 静默降级为仅悬浮条，药丸 tooltip 注明「系统通知未授权」。

## 配置

**无配置项**：插件不读设置、不提供配置卡片，`cordis.patch.yml` 只插入一行 Host 空插件，不接收 `config`。唯一写盘动作是药丸位置偏好写 `localStorage["pending-sessions/pill-position"]`（比例坐标，UI 偏好，不是会话状态）。

node plugins/pending-sessions/test.mjs

73 个离线用例，覆盖：

- **信号与排序**：三类阻塞信号、未读信号、混合排序（阻塞在前、组内按更新时间倒序）、无归属工作区、`default-workspace` 名称回退、只在状态里出现的会话、当前主视图排除。
- **过滤**：子智能体既不列表也不通知、孤儿 id 保留；等待子智能体的父会话抑制（直接子 / 嵌套孙、子会话仅未读不算活跃、子会话等待交互算活跃、父会话自身交互不抑制、孤儿行 / 缺 `parentSessionId` 不抑制、多父会话、环终止、等待集保留与移出）。
- **药丸**：运行计数、三色 tone 优先级（阻塞 > 运行 > 未读 > 空闲）、脉冲通道、分类计数显示条件、收起态隐藏待处理数量与警示色、头部摘要。
- **收起与展开**：一键收起全部待处理 id、手动恢复、新待处理自动恢复、已收起 id 离开后清除且 re-enter 算新 episode、刷新即空集、自动展开的边沿判定与基线快照例外。
- **位置**：默认右下角、四边 8px 钳制、比例 ↔ 像素往返、窗口缩放 / 最大化后同一比例保持同一相对位置、旧像素格式迁移、畸形输入与不可用存储兜底。
- **拖动与面板**：≥400ms / >10px 两个阈值、未达标松手仍是点击、面板朝向与视口钳制、窄窗宽度与可用高度上限。
- **通知**：边沿 / 同 episode 只一次 / 批量合并摘要 / 聚焦不弹 / 权限被拒静默。
- **集成**：服务缺失时 `apply` 只告警不激活、清单字段、`locale/*.json` 与 `client.js` 内置字典逐键同步。

人工验收（装到 desktop profile、重启 DSH 后）：

1. 开两个工作区各跑一个会话：A 触发提问（等回答 / 等批准），B 回合跑完（未读回复）→ 右下角悬浮条计数 = 2；当前主视图的会话不出现在列表里。
2. 状态色：只跑一个会话 → 蓝点脉冲 + 「N 运行中」；开启系统「减少动态效果」后脉冲变静态、颜色与文字不变；停止后 → 灰点「全部空闲」；制造「等回答」→ 黄边黄点「1 待处理」；再让另一个会话跑起来 → 仍是黄边黄点**且脉冲**、文字「1 运行中 · 1 待处理」；跑完停在未读 → 绿边绿点「1 待读」；阻塞 + 未读并存 → 黄色优先「1 待处理 · 1 待读」。
3. 点开悬浮条：摘要行、状态点、类型标签、工作区名、会话标题逐项核对；逐项点击跳转并处理 → 条目逐个消失。
4. 收起与展开：点「暂时收起」→ 药丸变低调、不显示数量 / 警示色（运行脉冲照常）→ 让一个会话新进入待处理 → 计数 / 警示色恢复但面板不自动弹；点低调药丸或「恢复」按钮 → 手动恢复并展开；点「×」关闭面板后制造新待处理 → 面板自动展开；刷新页面后收起状态复位，已有待处理只显示计数。
5. 拖动：收起态长按约 0.5s（或直接拖 >10px）→ 药丸浮起跟随 → 松手落在任意位置，拖到边缘时被挡在 8px 内；快速单击仍只展开、不拖动；拖到上半屏展开 → 面板向下，拖到下半屏 → 面板向上；刷新 / 重启 → 位置保留；窗口缩小再最大化 → 同一比例重新锚定。
6. 通知：切到别的窗口，在某个会话制造一次新待处理 → 收到系统通知；两条同时出现只收到一条摘要；拒绝通知权限 → 不再弹，tooltip 显示未授权；等待子智能体时父会话不通知，整批结束只提醒一次。

## 已知限制

- `completionUnread` 是纯客户端内存，刷新页面即丢；打开页面前已完成的冷会话不会出现；`pendingInteraction` 较耐久，但 Host 重启后仍会丢。
- 运行计数只含本客户端观察到的会话；页面打开前已结束或从未出现在 `sessionStatus` 的会话不计入。
- 收起集纯内存，刷新页面 / 连接代际 reset 即复位，不写盘、不跨重启。
- 位置是 UI 偏好，不是会话状态：以比例坐标存 `localStorage`，是本插件「零自造持久状态」的唯一显式例外；存储不可用时降级为本次页面内存。`hostViewportOf` 仍是「两级父容器 + window 兜底」的猜测，overlay 尺寸测不准时基准会偏。
- 子智能体自己卡在等批准 / 等回答时仍不单独列出；等待判定只看「父会话 unread + 后代有活跃节点」，父会话异常一直不被唤醒会一直被隐藏，没有超时兜底。
- 快照时序风险：若父会话 `running → false` 先于子会话 `running` 到达，首帧可能判不成等待而误弹一次；离线无法构造该顺序，人工验收若复现再补约 250ms 的 settle 延迟。
- 自动展开是边沿驱动：首次加载 / reset 后已存在的待处理只显示药丸计数，不弹面板。

## 实现要点

功能全部在浏览器半区 `client.js`，Host 侧没有任何逻辑；`plugin.mjs` 是 `apply(){}` 空实现，只为让 Loader 行存在。客户端 bundle 按**激活的 Loader 条目**逐条发现，只带 `client.js`、没有 Host 入口的包永远扫描不到（依据：DSH 桌面版 `app.asar` 内的 `dsh-client-modules`，2026-11-05 只读取证）。

| 事实 | 依据（asar 内路径） |
|---|---|
| 客户端 bundle 按激活的 Loader 条目发现；`dsh.client.platform` / `exports["./client"]` 缺一就不进 Web graph | `dsh/node_modules/@deepseek-ai/dsh-client-modules/lib/index.js` |
| 浏览器半区是手写的 `window.__ModuleLoader__.load({id, factory})` 纯 JS，Host 按字节直读、不转译；`id` 必须等于包名 | 同上（boot 协议） |
| 待处理信号：`uiSession.sessionStatus` 是 `Map<sessionId,{running,pendingInteraction,completionUnread}>` | `dsh-client-ui-session/lib/client.js` |
| `pendingInteraction.kind` ∈ `approval` / `question` / `plan-review` | `dsh-client-ui-approval/lib/client.js`、`dsh-client-ui-user-questions/lib/client.js` |
| 工作区归属用 `workspaces.items[].sessionIds` 反查；当前主视图取 `uiWorkspace.selection` | `dsh-client-ui-workspace/lib/client.js` |
| 悬浮条落点 `shell.overlay`（list / root） | `dsh-client-ui-workspace/lib/client.js`、`dsh-client-ui-layout/lib/client.js` |

过滤 / 排序 / 工作区映射 / 主视图排除 / 子智能体过滤 / 等待父会话抑制 / 通知边沿与合并 / 药丸状态与颜色 / 临时收起 / 位置钳制与比例换算 / 拖动手势 / 面板朝向全部是 `client.js` 导出的纯函数（`exports.pure`），可在 Node 下零依赖回归。

## 回滚

- 临时停用：插件页关掉该组合包，或在 profile 的 `cordis.patch.yml` 给该行加 `disabled: true`；重启 DSH、刷新页面后悬浮条消失。
- 彻底移除：插件页移除，或 `dsh plugin --profile desktop remove pending-sessions`。
- 清位置偏好：删除 `localStorage["pending-sessions/pill-position"]`，药丸回到右下角默认。
- 以上都不影响已有会话；插件不写会话状态，卸载不清会话数据。
