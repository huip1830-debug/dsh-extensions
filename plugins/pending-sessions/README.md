# pending-sessions

> 部署状态以 profile 安装为准（`dsh plugin --profile desktop list`）。改动后：提交推送 → 关闭 DSH → `dsh plugin --profile desktop update pending-sessions` → 启动。

DSH GUI 插件：**默认右下角、可长按拖动换位的全局悬浮条**，列出等你处理的会话——阻塞等待（等批准 / 等回答 / 计划复核）与回合结束未读回复两类都算，并常显「运行中 / 待处理 / 全部空闲」三态，让你一眼知道「是在等回复，还是没有会话在工作」。暂时不方便处理时一键收起，等新待处理出现自动恢复。药丸可长按拖动到顺手的位置（自由放置、按比例记住位置，窗口缩放 / 最大化后仍落在同一相对位置）；点条目跳转，处理后自动消失（无手动已读）；窗口失焦时尽力弹系统通知。

- 权威设计：[`docs/superpowers/specs/2026-11-05-pending-sessions-design.md`](../../docs/superpowers/specs/2026-11-05-pending-sessions-design.md)
- 实施计划：[`docs/superpowers/plans/2026-11-05-pending-sessions-plan.md`](../../docs/superpowers/plans/2026-11-05-pending-sessions-plan.md)

## 行为

| 场景 | 行为 |
|------|------|
| 有会话在运行（`running === true`，**含子智能体**） | 药丸常显 + 圆点脉冲动画（纯 CSS keyframes 呼吸；`prefers-reduced-motion: reduce` 时降级为静态），文字「N 运行中」；取值为整个客户端观察到的运行会话数 |
| 运行中且有待处理 | 两种信号并存：药丸显示「N 运行中 · M 待处理」，展开列表照常 |
| 没有运行、有待处理 | 药丸 `● N`；有阻塞类时警示色 |
| 没有运行、没有可见待处理 | 低调药丸：三级灰小点 +「全部空闲」，不警示不闪烁，常显（「可安排新工作」） |
| 会话等批准 / 等回答 / 计划复核（`pendingInteraction`） | 算待处理，归「阻塞类」，药丸显示警示色 |
| 回合跑完但回复未读（`completionUnread`） | 算待处理，归「未读类」 |
| 两类混合 | 阻塞类整体在前，未读类在后；两类内部各自按会话更新时间倒序（最新在前） |
| 当前主视图会话 | 不进列表（已经在眼前） |
| 子智能体会话（`origin: 'subagent'`） | **不出现在列表与通知中**：不计数、不触发系统通知；孤儿 id（状态里有、会话列表里没有）无法证明是子智能体，照常列出。**运行计数例外**：刻意包含子智能体，是全局活动指示 |
| 父会话正在等待子智能体（其子智能体 / 孙智能体有运行中或等待交互的节点） | **不列、不弹通知、不计入待处理数量**：父会话的「回合结束未读」被识别为等待子智能体，不是等你读；药丸仍显示「N 运行中」（运行计数含子智能体）。整批结束、父会话真正跑完最后一轮且无活跃子智能体时，这一次未读才按普通未读提醒一次。父会话自己有等批准 / 等回答时照常提醒 |
| 暂时收起 | 展开面板头部「暂时收起」把当前全部待处理 id 压入控制器内存收起集（不写盘）；药丸不再显示待处理数量、不用警示色（运行动画不受影响），面板仍可查看全部条目 |
| 收起后新待处理 | 任何不在收起集里的会话新进入待处理 → 整个列表自动恢复；收起集中的 id 离开待处理后立即清除，之后再次进入算新 episode，同样触发恢复与通知 |
| 手动恢复 | 点击低调药丸 → 恢复并展开；面板内也可点「恢复」 |
| 面板关闭（×） | 回到药丸形态，不是临时收起：待处理仍在列表里 |
| 长按药丸（≥400ms）或按住移动 >10px | 进入拖动：药丸浮起（阴影加深 + 轻微上移）并实时跟随指针；**只在收起态可用**，面板展开时位置锁定。两个阈值都未满足的松手仍是原点击行为（展开 / 恢复） |
| 松手落点 | 自由放置（不吸附边缘），松手时先按当前视口与药丸实测尺寸换算成**比例坐标** `{fx, fy}`（可动区间 = 视口 − 药丸尺寸 − 两侧 8px 边距；`fx=fy=1` 即右下角）再写入 `localStorage["pending-sessions/pill-position"]`，跨刷新/重启保留；窗口缩放 / 最大化后按新视口换算回像素，始终落在同一**相对**位置（不再累积偏差）；旧版 `{left, top}` 像素偏好首次测量后一次性迁移为比例并写回；畸形 / 迁移失败回落右下角默认，绝不丢到窗口外；存储不可用时静默降级为本次内存；连接代际 reset 不复位位置（UI 偏好） |
| 展开面板朝向 | 药丸在下半屏 → 面板向上展开；上半屏 → 向下展开；水平贴药丸右缘并钳制在视口内（窗口过窄时面板收窄，过矮时限制高度） |
| 展开态 | 头部状态摘要行（如「2 运行中 · 1 待处理」/「全部空闲」）+ 列表项 = 状态点 + 类型标签（等批准 / 等回答 / 计划复核 / 未读回复）+ 工作区名 + 会话标题 |
| 点击条目 | `ctx.uiWorkspace.openSession(sessionId)`，等价侧边栏点击 |
| 处理完 | 全自动消失：跳转使会话成为主视图 → 未读清除；完成交互 → 领域撤销待处理。**不写任何已读表** |
| 窗口失焦 + 会话新进入待处理 | 弹一条系统通知；多条同时出现合并为一条摘要（「N 个会话待处理」） |
| 窗口聚焦 | 不弹通知（人已经在看） |
| 页面首次加载时已在待处理的会话 | 只进列表，不补发通知（通知只认「新进入」的边沿） |
| 通知权限被拒 / 环境不支持 | 静默降级为仅悬浮条，药丸 tooltip 注明「系统通知未授权」 |
| 会话持续待处理 | 同一 episode 只通知一次；处理掉之后再次进入才算新 episode；已收起项不重复通知 |

## 安装

包已声明 `dsh.bundle.patch`，所以 DSH 插件页可以直接装。桌面版或 Web 侧栏 **插件** → **添加插件** → **安装第三方插件**，填：

```
https://github.com/huip1830-debug/dsh-extensions.git#path:/plugins/pending-sessions
```

CLI 等价：

```powershell
dsh plugin --profile desktop add "https://github.com/huip1830-debug/dsh-extensions.git#path:/plugins/pending-sessions"
```

装完在插件页启用，重启 DSH。升级 = 同地址重装（插件页会提供"更新"）。卸载 = 插件页移除（或 `dsh plugin --profile desktop remove pending-sessions`）。

profile 层插件不支持热加载，**改完必须重启 DSH**；`client.js` 的改动同样要重启才生效。

## 配置

**无配置项**：插件不读设置、不提供配置卡片。唯一写盘动作是药丸位置偏好写 `localStorage["pending-sessions/pill-position"]`（§12/§13 的 UI 偏好，非会话状态，存比例坐标）；`cordis.patch.yml` 只插入一行 Host 空插件（见下节），不接收 `config`。要停用就在插件页关掉该组合包，或给该行加 `disabled: true`。

## 实现要点（为什么会有空的 plugin.mjs）

功能全部在浏览器半区 `client.js`，Host 侧没有任何逻辑；`plugin.mjs` 是 `apply(){}` 空实现，只为让 Loader 行存在。依据（2026-11-05 只读取证，DSH 桌面版 `app.asar`）：

| 事实 | 依据（asar 内路径:行号） |
|------|--------------------------|
| 客户端 bundle 按**激活的 Loader 条目**逐条发现：`processOne` 遍历 `ctx.loader.entries()`，跳过 `fiber === undefined` 或 `disabled` 的行 | `dsh/node_modules/@deepseek-ai/dsh-client-modules/lib/index.js:852-858` |
| 条目被挂载后，从该行的包清单读 `dsh.client.platform` / `exports["./client"]`；`platform !== 'web'` 直接不进 Web graph | `…/dsh-client-modules/lib/index.js:720-750`、`877-889` |
| 同理，声明了 `dsh.client` 却没有 `exports["./client"]` 会直接抛错（激活期聚合报错） | `…/dsh-client-modules/lib/index.js:737-738` |
| 因此只带 `client.js`、没有 Host 入口的包永远扫描不到；bundle patch 插入的 Loader 行必须能 import 到包根 | 同上（`ctx.loader.entries()` 为唯一发现入口） |
| 浏览器半区是手写的 `window.__ModuleLoader__.load({id, factory})` 纯 JS，Host 按字节直读、不转译；`id` 必须等于包名 | `…/dsh-client-modules/lib/index.js:460-505`（boot 协议） |
| 待处理信号：`uiSession.sessionStatus` 是 `Map<sessionId,{running,pendingInteraction,completionUnread}>` | `dsh-client-ui-session/lib/client.js:782-992` |
| `pendingInteraction.kind` ∈ `approval` / `question` / `plan-review` | `dsh-client-ui-approval/lib/client.js:180`；`dsh-client-ui-user-questions/lib/client.js:185` |
| 工作区归属用 `workspaces.items[].sessionIds` 反查（官方侧边栏同款） | `dsh-client-ui-workspace/lib/client.js:1027-1046` |
| 当前主视图会话 id：`uiWorkspace.selection` 快照存储的 `sessionId`（由 `replaceMain` 写入）；回退 `retainedBy.mainView > 0` | `dsh-client-ui-workspace/lib/client.js:1369`、`1652-1675`、`3544`；`dsh-client-ui-session/lib/client.js:973-975` |
| 悬浮条落点 `shell.overlay`（list/root）；overlay 容器 `absolute; inset:0; pointer-events:none`，子元素 `pointer-events:auto` | `dsh-client-ui-workspace/lib/client.js:5306`（注册先例）；`dsh-client-ui-layout/lib/client.js:73`（容器 CSS） |

决策逻辑（过滤 / 排序 / 工作区映射 / 主视图排除 / 子智能体过滤 / 等待子智能体的父会话抑制 / 通知边沿、节流、合并 / 三态药丸 / 临时收起折叠 / 位置钳制 / 比例↔像素换算 / 位置读写与旧格式迁移 / 拖动手势判定 / 面板朝向）全部是 `client.js` 导出的纯函数（`exports.pure`），可在 node 下零依赖回归。位置持久化是「零自造持久状态」的唯一显式例外（UI 偏好，§12.2 / §13）。

## 人工验收

1. 装到 desktop profile → 重启 DSH。
2. 开两个工作区各跑一个会话：A 会话触发 agent 提问（出现「等回答」或「等批准」），B 会话回合跑完（出现「未读回复」）→ 右下角悬浮条计数 = 2。
3. **三态验收**：让某个会话处于 agent 运行中 → 药丸圆点脉冲、文字「N 运行中」（开启系统「减少动态效果」后脉冲变静态）；所有会话停止 → 无待处理时药丸变低调灰点「全部空闲」，有待处理时维持数量药丸。
4. 点开悬浮条：头部状态摘要行显示「2 运行中 · 1 待处理」或「全部空闲」；逐项检查状态点 / 类型标签 / 工作区名 / 会话标题；逐项点击跳转并处理 → 对应条目逐个消失；当前主视图那个会话不出现在列表里。
5. **临时收起验收**：面板头部点「暂时收起」→ 药丸变低调「已收起」且不显示数量/警示色（若仍有会话在运行，脉冲与「N 运行中」照常）→ 再让一个会话新进入待处理 → 列表自动恢复；重新收起后点击低调药丸 → 手动恢复并展开；点「恢复」按钮同样恢复。刷新页面后收起状态复位。
6. **拖动验收**：收起态长按药丸约 0.5s（或按住直接拖动 >10px）→ 药丸浮起并实时跟随指针 → 松手落在任意位置（不吸附边缘；拖到窗口边缘时被挡在四边 8px 内）；快速单击药丸仍只展开面板、不进入拖动；把药丸拖到上半屏后展开 → 面板向下展开，拖到下半屏后展开 → 面板向上展开、右缘贴药丸右缘；刷新页面 / 重启 DSH → 位置保留；**把窗口缩小再最大化 / 恢复** → 药丸按同一比例重新锚定（例如拖到半屏高度处，缩放后仍在半屏高度附近），不再停在小窗旧坐标，且始终完整落在窗口内；面板展开时药丸不可拖动（位置锁定）。
7. **通知验收**：切到别的窗口让 DSH 失焦 → 在某个会话制造一次新的待处理（例如提问）→ 收到系统通知；首次触发应出现浏览器授权请求；两条同时出现时应只收到一条「N 个会话待处理」摘要，而不是两条；点通知尝试跳转到该会话（Electron 下窗口激活与否以实测为准）。
8. 拒绝通知权限 → 不再弹通知，悬浮条 tooltip 显示「系统通知未授权」。
9. 把所有会话处理完且无运行会话 → 药丸变为低调「全部空闲」常显（不再整体隐藏）。
10. **等待子智能体验收**：主控派 2 个子智能体后切到别的窗口（DSH 失焦）→ 两个子智能体逐个完成时**不**应收到主控会话的「未读回复」通知，悬浮条只显示「N 运行中」→ 主控最终跑完整个任务 → 只收到**一条**「未读回复」通知，悬浮条出现父会话条目且点击可跳转；对照：普通会话（无子智能体）回合结束仍照常通知；嵌套场景（主控 → 子智能体 → 孙智能体）孙智能体运行期间主控不通知。

## 已知限制

1. `completionUnread` 是纯客户端内存，刷新页面即丢——本插件是「本次打开 DSH 以来的提示板」，**不是**跨重启的待办清单。
2. 打开页面前就已完成的冷会话不会出现在列表（从未观察到它的 `running → false` 转换）。
3. `pendingInteraction` 较耐久（Remote waterfall 重连重放），但 Host 重启后仍会丢。
4. 系统通知依赖浏览器授权与 OS 通知中心设置；DSH 窗口聚焦时不弹是防打扰设计，不是缺陷。
5. **收起集纯内存**：刷新页面（或连接代际 reset）即复位，不写盘，也不跨重启保留。
6. **运行计数只含本客户端观察到的会话**：页面打开前就已结束、或从未出现在 `sessionStatus` 的会话不计入；子智能体计入（全局活动指示）。
7. **位置是 UI 偏好，不是会话状态**：药丸位置以**比例坐标** `{fx, fy}` 存 `localStorage["pending-sessions/pill-position"]`（跨刷新/重启保留；旧版 `{left, top}` 首次测量后自动迁移），是本插件「零自造持久状态」的唯一显式例外；localStorage 不可用（隐私模式/禁用）时静默降级为仅本次页面内存，位置仍可拖动。第 5 条的收起集**仍是纯内存**、刷新即复位，两者不混用。
8. **`hostViewportOf` 仍是两级父容器 + window 兜底的猜测**：overlay 宿主尺寸测不准时，比例换算的基准会偏（R3 已知风险）。比例语义使缩放 / 最大化不再累积偏差（同一比例按视口重算），但首次测量仍依赖该猜测；若极端布局下位置仍偏，改量 `window.innerWidth/innerHeight` 可作为后续修正。
9. **子智能体自己卡在等批准 / 等回答时仍不单独列出**：§10 的子智能体过滤把子会话整体隐藏，本次「等待子智能体的父会话抑制」只让父会话更安静，并不覆盖这个独立缺口（不要误以为已覆盖）。
10. **父会话异常不被唤醒会一直隐藏**：等待判定只看「父会话 unread + 后代有活跃节点」；若父会话因异常一直不被唤醒且保持 `completionUnread`，会一直被隐藏（正常子智能体完成事件会唤醒父会话），本次不做超时兜底。
11. **快照时序风险**：若父会话 `running → false` 的状态先于子会话 `running` 状态到达，首帧可能判不成等待而误弹一次；该事件顺序离线无法构造，先按快照实现，人工验收若复现再补一个短暂 settle 延迟（约 250ms 内重新确认等待集）。
