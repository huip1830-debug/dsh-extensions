## 2. 移除独立复跑的裁决（0.5.2 规则 3）

**动机（实测）**：一个评审任务中，评审子代理花了大量时间评审，主控又把验收/评审重复做了一遍——同一信号付了两到三次钱，时间成本与算力成本都偏高。

**裁决：接受此弱化，理由三条，边界一条。**

理由：
1. **复跑防的不是主要风险**。0.3.9 `tagify` 样本（README 设计取舍②）里，「实现与测试同一盲点」是语义评审抓出来的；命令复跑两边都绿，对共享盲点毫无作用。复跑实际只防「子代理声称跑过但没跑 / 谎报退出码」这一类窄风险。
2. **重复付费是实锤**。gated 批次的验收链原是「子代理窄验证 + 派发方复跑 + 评审语义核对」，其中前两项买的是同一个执行性信号；单一付费原则（10-27 spec §3.2）要求只付一次。0.5.2 把唯一一次留给子代理（窄验证负责归因），派发方的执行性预算集中在批末集成命令（负责集成状态），分工仍闭合。
3. **独立判断环节未减**。主控仍读 diff、仍跑集成命令并留存退出码；gated 批次仍有独立只读评审。被去掉的只是「同一命令的第二遍执行」，不是任何一道独立判断。

边界（必须同时成立，缺一则恢复复跑；**0.5.4 起已写进规则 3 注入文本**，此前只在文档层、模型看不到等于不存在）：
- **集成命令必须覆盖各批窄验证的断言点并集**。白名单本就以「全批结束后一条集成命令能验完」为界，此条是把该含义显式化为验收前提；若某批窄验证断言了集成命令覆盖不到的行为，该批的窄命令仍需派发方复跑。
- 残余风险收窄为：微批（免评审）+ 集成命令未覆盖的断言点 + 子代理谎报。对冲：主控读 diff 时核对其退出码报告与 diff 内容的一致性（diff 与「测试全绿」明显不符即起疑）；微批返工率度量卡（10-27 spec §8）对该风险有趋势观测。

注：「主控重复评审」的病灶严格说在评审层交接（主控不应重做语义评审，裁决归派发方≠派发方重审），0.5.2 动的是执行性验证层。两者同属双付费但口径分开记录，避免下次误把评审层问题再归到复跑头上。

## 3. 新增校准项（并入 10-27 spec §8）

5. **`15 分钟 / 30 次编辑` 切片阈值与「10 分钟首个可验收切片」为外推初值**：证据只有 `session-1433e747` 一个会话，无校准计划。纳入度量闭环：观察期内若判级升级通道频繁因「工作量显著超预估」触发，说明阈值偏松；若大量批次被切出过碎（启动成本/产出比回升 >1），说明偏紧。
6. **注入文本体积纳入每次改规则的例行核算**：0.5.0 为 +520 字算过 ROI，0.5.1/0.5.2 未算（本次补算见 §4）。今后改 DEFAULT_RULES / DEFAULT_FOOTER 时在提交说明里附字符增量。

## 4. 注入成本补核算（0.5.1 + 0.5.2）

| 版本 | 规则+footer 字符数 | 相对基线增量 |
|---|---:|---:|
| 0.4.x 基线 | 1299 | — |
| 0.5.0 | 1819 | +520 |
| 0.5.3（实测，`node -e` 导入 config.mjs） | 2223 | 较 0.5.0 **+404**（≈+270 tokens）；累计 +924（≈+616 tokens） |

按 10-27 spec §7 的口径（770 步/天、+700 tokens ≈ +5 万 fresh 等价/天）折算：0.5.1/0.5.2 增量 ≈ **+1.9 万 fresh 等价/天**，累计 ≈ +4.4 万/天。对实测可节省项（症状 1+2 每天数十万 fresh + 数百万 cache，外加 0.5.2 消灭的 sleep 轮询步进）ROI 仍 >10:1。**结论：体积增长可接受，未破坏 0.5.0 的成本论证。**

## 5. 遗留

- 10-27 spec §8 未决项 1–4 不变（价格比 k 实值、只读评审沙箱层、度量采集脚本、2 周观察期）。
- 若观察期内微批返工率或窄验证谎报案例出现，按 §2 边界条款恢复复跑，框架不动。
