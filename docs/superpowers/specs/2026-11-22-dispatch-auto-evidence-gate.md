# dispatch-protocol 0.20.0 — `auto` 请示的证据门槛：不写流程，写门槛

- 状态：**契约冻结**（2026-11-22，用户回「ok」＝接受门槛式措辞；同场讨论中用户否掉了流程式措辞：「这样约束大模型，他会按照这个流程执行」）
- 前序：`2026-11-18-dispatch-auto-mode-design.md`（auto 档与升级工具）、`2026-11-22-dispatch-auto-text-reframe.md`（0.19.0 中性框架 + 正面示例）
- 版本：`0.19.0` → **`0.20.0`**
- 非目标：不改四档语义；不改 `dispatch_upgrade_full` 契约；不加观测、提醒、检查点类机制；不引入关键词/文件数触发器；**不在 auto 引入任何流程性动作**（勘察、现状文件等）。

## 1. 问题与裁决脉络

0.19.0 之后讨论「判断时间在需求入口、手里无证据」的解法，用户否掉两个方向：

1. **流程式措辞**：「先按平常节奏读相关代码、摸清波及面，再回答判断题」——提示词对模型就是指令，写了流程它就会当流程执行，等于给 auto 强加一个勘察阶段，与「auto 不引入流程」的定位自相矛盾。
2. （沿用上轮裁决）观测机制与文本关键词触发，均不做。

剩下的可动杠杆只有一个：**把「有证据」写成请示的合法性条件，而不是一个前置动作**。流程会被执行，条件只在决策点被检查——模型没有新动作要做，只是「无证据的请示」失去合法性。证据的自然供给渠道：需求本身写明波及面的（入口即有证据）；需求模糊的，模型按自身节奏读代码时自然获得证据。两个时刻都无需提示词规定。

## 2. 契约（`AUTO_TEXT` 第二段，0.19.0 → 0.20.0）

三处变更，其余逐字保留：

1. **删入口时点**：首段「由你在收到需求时判断」改为「由你判断」——判断不再钉在需求入口。
2. **示例定性词**：「典型应该请示升级的情形」改为「典型受益的情形」——示例回答「什么时候受益」，「什么时候该问」由门槛条款回答。
3. **证据门槛**：删「反过来，单一模块内的小改、纯文案或配置调整、一次就能完成的修复，直接做、不必问」（被门槛句涵盖，且控制长度），新增「请示只在你能说出具体受益点（哪个契约面、哪些调用方、几个批次）时提出；说不出就不要问，直接做。」

保留不动的要素：四件事清单、「会不会从上面四件事中的至少一件显著受益」判断问句、三类典型受益情形、「每需求最多问一次」、「被拒后除非范围实质扩大，不再问」（许可式的中途再请示通道，措辞不动）、工具名与兜底文案、子代理条款。

禁止出现的措辞（测试断言）：「摸清波及面」「先勘察」「先…读相关代码」等任何流程式表述。

## 3. 兼容与风险

- **行为变化只有提示段正文**；auto 项目下一节起生效。
- **诚实代价**：门槛式主要杀掉入口处的瞎问，对「该问没问」的改善是间接的——赌模型在自然工作中获得契约面证据后，正例 + 门槛会促成请示。无观测手段（用户已定），效果只能体感。
- **门槛可能压制正当请示**：模型若把「说不出具体受益点」理解得过严，可能连有据的需求也不问。回退点：把门槛句放宽为「请示时说出具体受益点」（从前置许可改为内容要求）。
