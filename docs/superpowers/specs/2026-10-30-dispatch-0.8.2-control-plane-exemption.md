# 0.8.2 控制面路径豁免 + 两处文本澄清（冻结契约）

> 派发方：主控。依据：`dispatch/ledger/2026-10-30-dispatch-0.8.1-verification.md` 偏离 1/2/3（10 个误报样本 + cea2278e 轻批 0 使用 + 6/6 会话判级未进任务清单）。
> 状态：契约已冻结；实施批运行期间本文件只读。

## 一、要解决的问题

1. **机械层不识别控制面路径**：nudge 计数器（`nudge.mjs` `summarizeTurn`）、VerifyGate（`gates.mjs` `touchedWorkingTree`→`analyzeVerification`）、ReviewGate（`gates.mjs` `evaluateReviewGate`）对 write/edit 一律计数，导致写 `dispatch/ledger/*`、`docs/superpowers/specs/*` 这些规则 1 明许的控制面文件被误报为「不在主控白名单内」「评审已失效」「收口前有改动」。0.8.1 实测 3 个会话 9+ 次误报，并强制了冗余集成复跑。
2. **规则 4 与轻批豁免的优先级歧义**：「命中 gated 的批次另派只读评审」被读成「gated 需求内每个批次都必须评审」，cea2278e 因此 12 批全批、轻批 0 使用。
3. **判级载体过窄**：规则 6「写进任务清单」在 6/6 会话未被满足，判级实际落在台账/正文。

## 二、冻结契约

### 2.1 `lib/nudge.mjs`

新增两个导出（放在 `DEFAULT_WRITE_TOOLS` 之后）：

```js
export const DEFAULT_CONTROL_PLANE_PATTERNS = ['dispatch/state.md', 'dispatch/ledger/', 'docs/superpowers/specs/']
export function isControlPlanePath(path, patterns = DEFAULT_CONTROL_PLANE_PATTERNS) {
  if (typeof path !== 'string' || path === '') return false
  const normalized = path.replaceAll('\\', '/').toLowerCase()
  return patterns.some(fragment => normalized.includes(fragment.toLowerCase()))
}
```

- `resolveNudge`：新增可选配置 `controlPlanePatterns`，缺省取 `DEFAULT_CONTROL_PLANE_PATTERNS`；校验同其它字符串数组（非空字符串数组，错误前缀 `dispatch-protocol: nudge.controlPlanePatterns`）；返回值携带该字段。
- `summarizeTurn`：write/edit 调用取到路径后，若 `isControlPlanePath(path, config.controlPlanePatterns ?? DEFAULT_CONTROL_PLANE_PATTERNS)` 为真，则**不计入** `writes` 与 `files`（pwsh 壳变更无路径，口径不变）。`failedWrites` 口径不变。
- 注释补一句：0.8.2 控制面写入（state/ledger/specs）是主控的合法动作，不是漏派发信号。

### 2.2 `lib/gates.mjs`

- 顶部 import 追加 `DEFAULT_CONTROL_PLANE_PATTERNS, isControlPlanePath`（来自 `./nudge.mjs`）。
- `resolveGates`：新增顶层可选配置 `controlPlanePatterns`（校验同上，错误前缀 `dispatch-protocol: gates.controlPlanePatterns`）；解析结果同时挂到顶层与 `verify`、`review` 两个子段（`verify.controlPlanePatterns`、`review.controlPlanePatterns`）。
- `touchedWorkingTree(call, results, patterns = DEFAULT_CONTROL_PLANE_PATTERNS)`：write/edit 分支先取路径，命中控制面 → 返回 false。pwsh 分支不变。
- `analyzeVerification` 签名不变；内部调用 `touchedWorkingTree(event, results, verify.controlPlanePatterns ?? DEFAULT_CONTROL_PLANE_PATTERNS)`。
- `evaluateReviewGate`：扫描 write/edit 时跳过命中 `gates.review.controlPlanePatterns ?? DEFAULT_CONTROL_PLANE_PATTERNS` 的路径（既不计 `changes` 也不入 `files`）。
- `plugin.mjs` 不改：三个入口（`evaluateVerifyGate` / `evaluateReviewGate` / `summarizeTurn`）都已传解析后的配置对象，豁免随配置对象流动。

### 2.4 `test.mjs`

保留全部现有断言。新增（位置自定，建议放对应套件末尾）：

1. nudge：一回合写 2 个控制面文件（如 `dispatch/ledger/x.md`、`docs/superpowers/specs/y.md`）、无派发 → `shouldNudge` false。
2. nudge：写 `dispatch/ledger/x.md` + `src/a.ts` 两个文件、无派发 → false（只有 1 个计数文件）；再写 `src/b.ts` → true。
3. VerifyGate：成功 `npm test`（exit 0）之后 edit `dispatch/ledger/x.md`，随后 present → `evaluateVerifyGate` 返回 null；改为 edit `src/a.ts` → 触发。
4. ReviewGate：`{ pending: true, warned: false, since }` 之后写 `dispatch/ledger/x.md` → null；写 `src/a.ts` → 触发且 files 含该路径。
5. `resolveNudge` / `resolveGates`：`controlPlanePatterns` 覆盖生效（自定义片段命中自定义路径）；传空数组或含非字符串 → 抛对应前缀错误。
6. 文本断言：`/任务清单或台账首行/`、`/判为轻批的批次除外/`。
